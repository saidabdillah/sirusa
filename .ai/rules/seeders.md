# Seeders

## Route names and menu scopes are camelCase and must match MenuSeeder
`Menu` scopes and route names are all-lowercase dot.separated (`admin.menukelola`, NOT `admin.menuKelola`). `EnsureMenuAccess` matches a route by `str_starts_with($routeName, $scope.'.')`; a menu whose `route` names a route that no longer exists no longer crashes the sidebar (`Menu::linkUrl()` falls back to a URL that 404s), but casing should still match the route table exactly. When adding or renaming a route under a menu, update the seeder in the same commit. `MenuSeeder` is idempotent: menus use `updateOrCreate` keyed on `(section, label, parent_id)` (label alone is ambiguous -- "Daftar Beasiswa" exists in two sections), grants use `insertOrIgnore` (the pivot has a composite primary key), and `buangMenuLama()` prunes menus + orphans left behind by a rename. Running it twice must leave the same 20 menus (10 top-level + 10 anak) and the same grants. **`buangMenuLama()` trap (documented, NOT to be fixed):** it prunes any menu whose label is not in the seeder's allow-list, so menus an ADMIN created through "Kelola Menu" are silently DELETED on the next re-seed — that is a known destructive side effect of re-seeding, not a bug to chase. **Giving a UI-created menu a route/scope:** route/scope are KODING-ONLY (no form inputs), so to point an admin-created menu somewhere, add the SAME `(section, label, parent_id)` row to `MenuSeeder` with `route`/`scope` set — `updateOrCreate` matches the existing row and fills the two columns on the next `db:seed` (and it only survives `buangMenuLama()` if that row is in the allow-list). One-off alternative: `php artisan tinker`.

## `Menu::sections()` is now DYNAMIC (no allow-list)
`Menu::sections()` returns `DEFAULT_SECTIONS` ∪ every distinct `menus.section` in the DB (`orderBy('urutan')->orderBy('label')`, no static cache). A menu in a section absent from `DEFAULT_SECTIONS` is no longer invisible — the sidebar will render its header — so the old "allow-list" warning in `.ai/rules/admin.md` no longer applies to `sections()`. What still needs `db:seed`: MOVING a menu between sections (the `updateOrCreate` key includes `section`, so the stale row in the old section survives until `buangMenuLama()` cuts it) and any label/grant change.

## Kunci grant menu yang tidak ketemu harus gagal keras
Kunci grant adalah `scope` menu, atau `Str::kebab($label)` untuk menu tanpa scope (mis. "Master Data" -> `master-data`). Kunci label rapuh: begitu labelnya diubah, kuncinya ikut berubah dan grant-nya hilang tanpa jejak. Gejalanya cuma "menu tiba-tiba tidak muncul" di sidebar, jauh lebih sulit ditelusuri daripada error saat seeding. Karena itu `pasangGrant()` melempar RuntimeException untuk kunci yang tidak ketemu, bukan `continue` diam-diam. Setelah mengganti label atau section di seeder, jalankan `php artisan db:seed` dan pastikan tidak ada exception.

## Ganti section/label di seeder = WAJIB `php artisan db:seed`
`section` ikut menjadi bagian kunci `updateOrCreate(['section','label','parent_id'])`. Karena `Menu::sections()` kini dinamis (DEFAULT_SECTIONS ∪ section di DB), section lama TIDAK membuat menu hilang -- yang terjadi justru sebaliknya: baris lama masih punya section lama, jadi sidebar menampilkan DUA header (lama + baru) sampai `buangMenuLama()` memotongnya. Gejala khas: header section kembar / label section basi di sidebar. Langkah wajib: (1) kalau urutan/nama DEFAULT-nya berubah, edit `DEFAULT_SECTIONS` di `app/Models/Menu.php` (untuk header yang belum punya menu); (2) `php artisan db:seed` dijalankan supaya baris lama benar-benar pindah. Efek samping lain: sesi user yang masih terbuka memegang sidebar dari grant lama sampai page reload.

## Section sidebar = pengelompokan tampilan, bukan kontrol akses
Section tidak menambah atau mengurangi permission: `role_menu` tetap satu-satunya sumber akses, dan `User::sidebarMenus()` tidak memfilter `section` sama sekali (hanya `parent_id` null + `aktif` + granted). Jadi saat memindahkan menu ke section lain, `scope`, `route`, `icon`, `urutan`, dan isi `$grants` TIDAK boleh ikut berubah -- kalau ikut berubah, itu perubahan permission, bukan perubahan tampilan, dan harus diuji sebagai perubahan akses. Pasangan label -> section beserta urutannya saat ini dikunci di `tests/Feature/SeederTest.php` ("setiap menu punya section yang sesuai di sidebar") supaya edit seeder tanpa `db:seed` langsung ketahuan.

## Label menu verifikasi sudah dipangkas, jangan dikembalikan; Kesra kini dropdown
Menu verifikasi di section `Verifikasi`: `Catpil` dan `Kampus` adalah leaf top-level; `Kesra` adalah induk dropdown (route DIHAPUS/null, scope tetap `admin.kesra`) berisi dua anak -- `Keputusan` (route+scope `admin.kesra.disetujui`, urutan 1; label lama `Disetujui` diganti pengguna -- route/scope TIDAK berubah, jadi grant tidak ikut berubah, tapi seeder WAJIB dijalankan supaya baris lama terpotong `buangMenuLama()`) dan `Verifikasi` (route+scope `admin.kesra.index`, urutan 2). Label lama `Verifikasi Catpil`/`Verifikasi Kampus`/`Verifikasi Kesra` dilarang dikembalikan (prefiksnya dihapus karena header section sudah menyebut prosesnya). Dua jebakan bentuk baru ini: (1) scope anak WAJIB unik dan tidak boleh sama dengan scope induk, karena `keyToId` grant memakai `scope` -- kalau anak memakai `admin.kesra`, kunci induk tertimpa dan grant induk hilang (dropdown tidak muncul); (2) anak harus ikut di-grant sendiri ke role (super_admin & kesra), karena `sidebarMenus()` hanya me-render anak yang grant-nya sendiri terisi -- induk ter-grant tapi anak tidak = sidebar jadi menu tanpa sub-menu (anak yang tidak ter-grant tidak dirender). Akses route `admin.kesra.*` tetap lewat scope induk (prefix-cover), jadi tidak ada perubahan permission di `EnsureMenuAccess`. Konsekuensi lama tetap berlaku: `Kampus` dipakai dua menu (Verifikasi & Administrasi) -- tes sidebar WAJIB mencocokkan `href`/`scope`, bukan teks label, dan teks konfirmasi hapus di "Kelola Menu" jadi ambigu. String "Verifikasi Catpil/Kampus/Kesra" di `app/Support/VerifikasiAntrean.php` dan `DashboardController::actorLabel()` adalah nama tahap/aktor, bukan label menu -- sengaja tidak ikut diubah.

## Seed data harus konsisten dengan satu-keputusan-satu-pendaftaran
`verif_kesra` di seeder harus diturunkan dari status `pendaftar` (ada yang `diterima`/`ditolak` => `setuju`), sama seperti `KeputusanPadderanController::update()`, dan `diputuskan_at` diisi hanya untuk yang sudah diputuskan. Menulis kedua nilai secara terpisah menghasilkan mahasiswa dengan pendaftaran `diterima` tapi `verif_kesra = 'menunggu'` — kombinasi yang mustahil terjadi di aplikasi tapi langsung merusak angka dasbor. Perhatikan juga: `UserSeeder` TIDAK dipanggil `DatabaseSeeder` (sengaja dikomentari di sana), jadi test konsistensinya harus memanggil `UserSeeder` secara eksplisit setelah `DatabaseSeeder`.

## Status Verifikasi leaf di section Administrasi, di-grant ke catpil & kampus juga
"Status Verifikasi" (`admin.kesra.status`) adalah LEAF top-level di section **Administrasi** (urutan 31, ikon fa-clipboard-list), BUKAN anak dropdown Kesra dan BUKAN lagi di section Verifikasi. Di-grant ke kesra, super_admin, Catpil, dan Kampus. Anak Kesra hanya dua: Keputusan (`admin.kesra.disetujui`) + Verifikasi (`admin.kesra.index`). Pindah leaf cukup dengan updateOrCreate(section,label,parent_id null); `buangMenuLama` membersihkan baris section lama saat seeder dijalankan.

## Status Verifikasi moved to Administrasi (urutan 31)
MenuSeeder now places the top-level leaf "Status Verifikasi" (route/scope `admin.kesra.status`) in section **Administrasi**, urutan 31 -- NOT section Verifikasi -- so Catpil/Kampus/Kesra/super_admin all find the rekap under Administrasi alongside Pendaftar/Master Data. It is granted to kesra, super_admin, catpil, and kampus. `buangMenuLama()` prunes the stale section-Verifikasi row on re-seed, so `php artisan db:seed --class=MenuSeeder` is required after this change. Totals are now 20 menus (10 top-level + 10 children). SeederTest locks `$status->section === 'Administrasi'`; MenuSidebarTest asserts the href appears in the Administrasi block and NOT in Verifikasi.
