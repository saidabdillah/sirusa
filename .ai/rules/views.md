# Views

## No Bootstrap flash alerts rendered
Do not render `session('success')`/`session('error')` as Bootstrap `.alert` boxes in ANY view (decision Oct-2026: all ~24 flash blocks removed). Success feedback is handled by the global SweetAlert in `custom.js` (`submitAjax`), so a flash block is pure noise. Keep STATIC/informative alerts (info panels, status badges, "Program Studi belum terisi", missing-upload warnings, landing infos). A failed login still shows its message because `AuthController` uses `withErrors(['login' => ...])` + inline `@error`, not a flash. Server-side `session('success')` may still be SET (tests assert `assertSessionHas('success')`), it just must not be RENDERED.

## Tombol aksi kartu ditaruh di dalam card-body, bukan card-footer
Kartu grid memakai `h-100` (equal-height), jadi `card-footer` mepet ke dasar kartu dan tombol aksi tampak "jauh turun". Pada `user/beasiswa/index.blade.php` (dan kartu mahasiswa serupa) tombol "Lihat Detail" ditaruh di dalam `card-body` setelah baris "Periode Pendaftaran" (`<div class="mt-3">`), pola yang sama seperti dasbor. Jangan mengembalikan `card-footer` untuk tombol semacam ini.

## No HTML required attribute in forms
Do not add the HTML `required` attribute to form fields. Validation is enforced server-side via Form Requests (wali/guardian fields on the profil form are conditional via `required_if:ikut_kk,<ayah|ibu|wali>`). Keep the red `*` span in labels as a visual hint only. Convention after the required-field audit (Oct 2026): every label of a server-side-required field carries `<span class="text-danger">*</span>`; conditionally-required fields (e.g. `kampus_id`, `required_if ... ditolak`) keep a STATIC star; nullable/optional fields and filter/search forms stay starless. Two documented exceptions: `auth/masuk` (login — user decision: login pages stay plain) and checkbox GROUPS, which star their heading instead (see `.ai/rules/beasiswa.md`).

## Pendaftaran has no upload form anymore
The `user/pendaftaran/buat` page is a CONFIRMATION page (profile summary + note about verified status), NOT an upload form. It has no file inputs, no `@push('script')` block, and no client-side file validation. All documents come from the profil; the pendaftaran request accepts only `beasiswa_id`.

## Profil is the single source of documents
The profil form (`profil.index`) is the only upload surface: `foto_profil`, `dokumen_*`, `ktp_ayah/ibu/wali`, `kk_wali`, `dokumen_prestasi[]`. Parent (ayah/ibu) fields are always shown; the WALI section (`#section-wali`) and wali-doc uploads toggle on the `ikut_kk` radio === `wali` — client-side via `updateWaliVisibility()` (`$('#section-wali').toggle(...)` + `$('.wali-doc').toggle(...)`) and the same `display:none` inline style server-side when `ikut_kk` is not `wali`. `status_orang_tua` was removed: the column was dropped from `profil_pengguna` in its in-place migration, and the field is gone from `UpdateProfilRequest`, `UserProfile::$fillable`, `User::getRequiredProfileFields()`, `lang/id/validation.php`, `UserSeeder`, and the profil form.

## Profil form: penghasilan removed + documents grouped
The income selects `penghasilan_ayah/ibu/wali` were removed from the profil form (the columns were dropped from `profil_pengguna` in its in-place migration; also gone from `UpdateProfilRequest`, `UserProfile::$fillable`, `User::getRequiredProfileFields()`, `lang/id/validation.php`, and the 3 read views). Uploaded documents render in three groups from `$documentGroups` passed by `ProfileController@index`: **Berkas Data Diri** (`foto_profil` + `dokumen_ktp`/`kk`/`desil`/`sktm`), **Berkas Kampus** (`dokumen_transkrip`/`surat_aktif`/`surat_pernyataan`/`bukti_ukt` — surat_pernyataan counts as kampus), **Berkas Orang Tua/Wali** (`ktp_ayah`, `ktp_ibu`, plus `$waliDocFields` = `ktp_wali`+`kk_wali` hidden unless `ikut_kk` is `wali`). `dokumen_prestasi[]` stays its own optional block after the groups. `dokumen_akta` (Akta Kelahiran) was REMOVED entirely (column dropped in-place, and gone from fillable/request/`getRequiredProfileFields`/`$documentGroups`/`UserSeeder`/views/tests). `jenis_kelamin` is now a pair of `custom-control custom-radio` inputs (values `Laki-laki`/`Perempuan`), no longer a `<select>`. Pas Foto (`foto_profil`) is now uploaded/flat listed like any other file (it is the first item of `$documentGroups['Berkas Data Diri']`); the old avatar preview widget (`#previewImg` + `foto_profil` change-listener JS + `skeleton form` `avatar => true`) was removed — but `foto_profil` still feeds the navbar avatar via `navbar.blade.php`.

## Profil detail views share one partial
The two "lihat detail" pages — `user/pendaftaran/lihat` and `admin/verifikasi/lihat` — render their left column (`col-lg-8`) from the SHARED partial `resources/views/partials/profil-detail.blade.php` (nominal name `partials.profil-detail`). It takes `profile` (nullable-safe), an optional `showDownloadDocs` param that nothing passes `true` for anymore (the `admin/pendaftar/lihat` consumer was deleted — the pendaftar module is fully read-only now), and an optional `stage` param that scopes the visible cards/sections per verification stage (see "Verification pages scope profile data per stage" below). The partial renders 4 cards in the SAME ORDER as the profil form (`profil/index`: Data Diri → Data Kampus → Data Orang Tua & Wali → Dokumen) and grouped like the PROFIL form, not legacy applicant columns: **Data Diri** (nama, email, nik, no_kk, jenis kelamin, TTL, agama, telepon, **desil**, kabupaten, kecamatan, desa, alamat — desil belongs here, mirroring `profil/index` where it sits next to telepon; NO Username field — username is deliberately not shown on any detail page, and the `admin/verifikasi/index` table has no Username column either), **Data Kampus** (title "Data Kampus", NOT "Data Pendidikan" — sourced from the PROFILE: `$profile->prodi?->fakultas?->kampus?->nama_kampus`, `$profile->prodi?->fakultas?->nama`, `$profile->prodi?->nama`, ipk, semester, nim, ukt formatted `Rp`), **Data Orang Tua &amp; Wali** (heading matches the profil section; opens with an "Ikut KK" indicator showing `ucfirst($profile->ikut_kk)`, then Nama+NIK+Pekerjaan for ayah and ibu; wali Nama+NIK+Hubungan+Pekerjaan only when `kk_ikut_wali` — so `desil`/`kk_ikut_wali` are NOT in the kampus card anymore), and **Dokumen Pendukung** (3 sections + `dokumen_prestasi`). The right column (status/aksi/admin form) stays page-specific. Do not inline per-page profile cards anymore — extend the partial instead.
Card layout: the three info cards use a uniform pattern `<div class="text-muted small">label</div><div class="font-weight-bold">value</div>` in a responsive `row`. The **decision dropdowns** on the admin action cards deliberately lead with a `-- pilih --` placeholder (`value=""`, `selected` when no `old()`/current status matches) so there is NO default answer: `admin/verifikasi/lihat` "Keputusan" (status `setuju`/`revisi`/`tolak`). Submitting the placeholder fails validation ("Status verifikasi harus dipilih.") — that is intended, it forces an explicit choice. Do not re-add a default-selected real option. (The old `admin/pendaftar/lihat` "Status" dropdown is gone with the read-only pendaftar module.) Data Kampus is a strict 3-COLUMN grid (~`col-md-4` each): row 1 Nama Kampus/Fakultas/Program Studi, row 2 IPK/Semester/NIM, UKT full-width `col-12` (IPK & Semester are NOT isolated/paired with Prodi). The "Ikut KK" indicator in the Data Orang Tua &amp; Wali card is a row of DISABLED `custom-control custom-checkbox` inputs labelled `KK Ayah`/`KK Ibu`/`KK Wali`, each `checked` when `(profile->ikut_kk ?? null) === 'ayah'|'ibu'|'wali'` (i.e. only the matching one is checked; it is read-only display, not a form). Ayah/Ibu/Wali keep sub-heading `h6.text-muted` rows. The **Dokumen Pendukung** card is COMPACT on all detail pages: each doc is a `col-lg-6` flex row with label on the left and Lihat/Download ("Tidak ada" when missing) on the right — they do NOT stack one-per-line full-width. Only the profil FORM (upload surface) keeps the stacked `input-group` layout; do not change it.

## Beasiswa periode & UKT cleave
`beasiswa` now stores a PERIOD: `tanggal_mulai` + `tanggal_selesai` (both `date`) instead of a single `batas_waktu`, and the `cakupan` column (the "Tunjangan" select, enum `penuh`/`sebagian`) was REMOVED. All deadline semantics use `tanggal_selesai`: `Scholarship::isExpired()` (→`isPast()`), `User\BeasiswaController::index` and `DashboardController` `where('tanggal_selesai','>=',now())`, dasbor badge `diffInDays(now())`. Admin create/edit form have two flatpickr fields (`tanggal_mulai`, `tanggal_selesai`); `StoreScholarshipRequest` validates mulai `after:today`, selesai `after_or_equal:tanggal_mulai`; `UpdateScholarshipRequest` the same minus `after:today`. The admin index DataTable "Batas" cell shows `mulai - selesai` (`renderBatasWaktu()`).
The profil form's UKT input is `type="text"` with a `Rp` input-group prepend and Cleave.js (`public/assets/modules/cleave-js/dist/cleave.min.js`, `<script src>` added inline at the top of the profil page's `@push('script')`; init `new Cleave('#ukt', { numeral:true, numeralThousandsGroupStyle:'thousand', delimiter:'.', numeralDecimalMark:',', numeralDecimalScale:0, numeralPositiveOnly:true })`) so it submits a string like `2.500.000`. `numeralDecimalMark` MUST stay distinct from `delimiter` — if omitted it defaults to `'.'` (same as the delimiter), and cleave then corrupts any formatted value that already contains a dot (typing past `1.000` resets/garbles the value). The comma is never displayed because `numeralDecimalScale` is 0. `UpdateProfilRequest::prepareForValidation()` strips `.` (alongside the `ikut_kk` merge) so the `numeric` rule still sees a plain integer.

## Menu views (super admin): matrix + kelola CRUD as modals
`resources/views/admin/menu/index.blade.php` is the roles×menus matrix (route `admin.menu.index`) rendered as a COLLAPSIBLE TREE: each top-level menu gets its own `<tbody>` with a `<tr data-tree-parent="{id}">` carrying a chevron toggle (`.tree-toggle`, `data-tree-toggle="{id}"`, `invisible` when there are no children); children are emitted in a following `<tbody class="tree-child-{id}" data-tree-child-of="{id}">` with `pl-5` indent, and a `@push('script')` handler toggles those tbody groups' `display` + swaps `fa-chevron-down/right` on click (children are VISIBLE by default, first click collapses them). It has NO per-row Ubah/Hapus and NO "Tambah Menu"; the only header-action is a `Kelola Menu` button to `admin.menukelola.index`. The PUT guard-form posts `grants[role_id][]` to `admin.menu.grants`.
`resources/views/admin/menu/kelola.blade.php` (route `admin.menukelola.index`) is the CRUD list WITHOUT separate additive pages: "Tambah Menu" and per-row "Ubah" are Bootstrap modals — partials `admin/menu/modal-tambah.blade.php` (single) and `admin/menu/modal-ubah.blade.php` (rendered once per parent row AND per child row, `$menu` + `$parents` + `$sections` passed in). ALL modal markup is wrapped in `@push('modal')` (written inside `@section('content')` so controller vars resolve) and the layout prints `@stack('modal')` at `<body>` level, right before `</body>` — this is REQUIRED because Bootstrap `position:fixed` modals nested under `.main-content`/`.main-wrapper` render behind their own backdrop (stacking context). Fields keep the same `name` attrs as before (`label`, `parent_id`, `icon`, `section`, `route`, `scope`, `urutan`, `aktif`, `wajib`) but every input `id` is namespaced per modal (`label-tambah`, `label-{id}`, …). Each form carries a hidden `modal_target` (its own modal id); on validation failure the controller `redirect()->back()`s and a `@push('script')` handler reopens `@json(old('modal_target'))` via `.modal('show')`. All `old()` values, `selected`/`checked` states, and `invalid-feedback` errors inside a modal are gated by `$isTarget = old('modal_target') === <modal id>` so a failed submit only repopulates/reopens the modal that was actually submitted (otherwise the flashed error would leak into every modal). Per-row Ubah button is a `<button data-toggle="modal" data-target="#modal-ubah-menu-{id}">`; Hapus stays a `.btn-delete-form` + `data-confirm-*` POST form with button `.btn-delete` (hidden only for `wajib` menus — deleting a parent with children is refused server-side).

## Role index uses modals too
`admin/role/index` renders "Tambah Role" as a modal (`#modal-tambah-role`, route `admin.role.simpan`) and each non-super_admin row an "Ubah" modal (`#modal-ubah-role-{id}`, route `admin.role.perbarui`) — partial `admin/role/modal-ubah.blade.php` — plus the `.btn-delete-form`/`.btn-delete` Hapus form. Same `modal_target` gating/reopen pattern and the same `@push('modal')`→`@stack('modal')` body-level rendering as menu modals. The deprecated `admin/role/{buat,ubah}`, `admin/menu/{buat,ubah}` page views no longer exist.

## Role & user index pages were slimmed down
`admin/role/index` lists roles with label badges (`$roleLabels`) and NO "Jumlah Pengguna"/"Menu Diaktifkan" columns; super_admin rows have no aksi buttons. `admin/pengguna/index` shows role as a colored badge and per non-super_admin row a dropdown button-group (**Ubah** → `admin.pengguna.ubah`, Nonaktifkan/Aktifkan `.btn-confirm-toggle`, Reset Password → POST form `admin.pengguna.reset-password` `.btn-confirm-toggle`, Hapus → DELETE form button `.btn-delete`) with DataTable init + per-page Swal handlers in `@push('script')`; the super_admin row has no buttons. `admin/pengguna/buat` and `admin/pengguna/ubah` render the peran `<select>` from the controller-supplied `$peranOptions` (`User::assignableRoleOptions()`) — 5 options for super_admin (User, Super Admin, Kesra, Kampus, Catpil — no `admin`), 4 for everyone else since `super_admin` is filtered out; never hardcode the list in the view. Both forms note that default/new passwords are `12345678`. The `admin/pengguna/ubah` form has NO email display, NO password fields, and NO NIK/NIM inputs — it only edits **Peran** and **Status** (Username is readonly). Email, password, NIK, and NIM are fixed after creation; password resets happen solely via the "Reset Password" quick action on the index.

## Pendaftar index is READ-ONLY (no detail action, keep the scroll-fix)
The `admin/pendaftar/index` page is a read-only server-side DataTable: there is NO Aksi column, NO `admin.pendaftar.lihat` route, and NO `admin/pendaftar/_aksi` partial anymore (all deleted with the pendaftar perbarui/hapus/info flows — the scholarship decision is NOT managed from pendaftar). The page carries a `@push('style')` block (marker comment `pendaftar-table-scroll-fix`) setting `box-sizing: border-box` on `#pendaftarTable th/td` to undo `datatables.css`'s `box-sizing: content-box` override — that override inflates the table a few px beyond the `.table-responsive` container and caused the thin horizontal scrollbar. Do not remove that style block; if the sliver reappears elsewhere, port the same override.

## Verification pages scope profile data per stage
`partials/profil-detail.blade.php` takes an optional `stage` param (null = show everything, used by `user/pendaftaran/lihat`). `admin/verifikasi/lihat` passes the stage so each verifier only sees their own remit: catpil = Data Diri + Data Orang Tua/Wali + doc sections "Dokumen Diri Sendiri" & "Dokumen Orang Tua / Wali"; kampus = Data Kampus + "Dokumen untuk Kampus"; kesra (final) + null = everything incl. Sertifikat Prestasi. The maps are `$stageCards` (diri|kampus|ortu|dokumen), `$stageDocSections` (document section names), `$showPrestasi`; sections are filtered with `array_intersect_key` so the `@unless($loop->first) <hr>` separator stays correct. Never fork the partial per page — extend the maps. Hiding a card in the UI is NOT a security boundary: `dokumen.show` only checks the file exists on disk.

## A lone staff card is left-aligned, not centered
`col-lg-N offset-lg-M` only centers at >=992px. Below that the column has no width class, so it becomes a `flex: 0 1 auto` flex item that shrinks to content width and sits hard left in the row. For a page that shows exactly one card (staff `/profil`), put `col-12 col-lg-N` on the card and `justify-content-start` on the `.row` — that keeps the card full width on mobile and pinned to the normal reading margin on desktop. Do NOT use `justify-content-center` here: a lone settings card floating in the middle of a wide screen reads as a layout bug, and the spec (batch 2, point 6) explicitly requires `justify-content-start` for every non-`user` role. Adding both offset and justify-content double-shifts on desktop.

## One loading standard, always released in `.always()`
Spinner-in-button goes through `submitWithSpinner($btn, teks)` in `public/assets/js/custom.js`, which stashes the original markup in `data-loading-html` and returns a `releaseSubmit()` closure. Call that closure from jQuery's `.always()`, never from inside `.done()`/`.fail()` — a 422 branch that returns early, or a network error (status 0), would otherwise leave the button `disabled + spinner`. Destructive actions additionally open a modal SweetAlert via `showSubmitLoading()`; that modal has no close button, so it MUST be closed by `closeSubmitLoading()` on every terminal path. Before opening it, call `FormTahanLoading($form)`: if the browser will block submit on native HTML5 validation, no request ever happens and the dialog would hang forever. `FormTahanLoading` returns false for `form[data-ajax-form]` because those validate on the server. Never write spinner HTML into a button from a view.

## Mark write forms with data-ajax-form, do not bind handlers per view
A single delegated `$(document).on('submit', 'form[data-ajax-form]')` handler in `public/assets/js/custom.js` does the work, so a view only adds the attribute. Do not add local `.btn-delete` / `.btn-confirm-toggle` submit handlers -- they would bypass the global one. Confirm buttons must call `$form.trigger('submit')`, never `$form[0].submit()`, or the AJAX handler is skipped.

## Setiap request di view wajib punya cabang gagal
Audit (April 2026): setelah semua form CRUD diarahkan ke `data-ajax-form` (satu handler `submitAjax` dengan `.always()`), hanya ada dua pemanggil request lain di views dan keduanya sebelumnya tidak punya cabang gagal: (1) `populateDesa()` di `profil/index.blade.php` memakai `$.getJSON(url, successCallback)` — select desa menganggur di "Memuat data..." selamanya saat request gagal; (2) `logout.info` di `layouts/partials/navbar.blade.php` memakai `fetch().then().then()` tanpa `.catch()` — klik Logout jadi tidak berefek tanpa pesan apa pun, dan 5xx balannya HTML sehingga `res.json()` melempar. Keduanya kini punya `.fail()`/`.catch()` yang membersihkan state loading lalu memberi pesan. Kalau menambah request baru di view, jangan pakai bentuk `$(url, successCallback)` atau `.then().then()` tanpa cabang gagal -- itu satu-satunya cara loading stuck lolos dari `submitAjax`.

## Tombol non-simpan wajib punya data-loading-text sendiri
Default submitWithSpinner() adalah 'Menyimpan...'. Tombol filter/search/masuk/menandai yang tidak menimpanya akan menampilkan teks yang salah saat diklik (tombol 'Cari' menulis 'Menyimpan...'). Setiap `button[type="submit"]` yang bukan aksi simpan wajib punya `data-loading-text` yang sesuai aksinya. Diuji di LoadingStandarTest 'tombol non-simpan punya teks loading yang sesuai aksinya'.
