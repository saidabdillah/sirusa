# Verifikasi

## No server-rendered empty-state row inside DataTables tbody
DataTables 1.10 maps `<td>` to columns by position and never honours `colspan`, so a single `@empty` row makes `_fnGetRowElements` return one cell and the initialiser throw on `_DT_CellIndex`. Use a bare `@foreach` (no `@empty`) and put the copy in the `language.emptyTable` option. `verifikasi/index.blade.php` was the only page that broke this.

## Dialog konfirmasi hanya untuk Setujui dan Tolak; opsi Tarik Kembali dihapus
Dropdown keputusan tidak lagi punya opsi "Tarik Kembali (kembalikan ke Menunggu)" -- keputusan jadi permanen setelah dibuat, dan `menunggu` tidak pernah jadi nilai yang bisa disubmit dari form. Konfirmasi SweetAlert memakai PETA `KONFIRMASI` (bukan rantai ternary, karena cabang `default`-nya dulu menyamar jadi teks penarik keputusan saat select masih `""`): hanya `setuju` -> "Yakin setuju?" dan `tolak` -> "Yakin ditolak?" yang dialog. `revisi` dan `— Pilih —` langsung `$form.trigger('submit')` tanpa dialog supaya pesan error inline (Catatan wajib / Status verifikasi harus dipilih) terlihat. Status `menunggu` dipetakan ke `""` saat menentukan opsi terpilih, dan select `pendaftar_status` juga punya placeholder supaya pendaftaran yang belum diputuskan tidak otomatis tampil sebagai "Terima".

## Dropdown keputusan verifikasi selalu dibuka kosong
Semua dropdown keputusan di `admin/verifikasi/lihat.blade.php` — profile (`status`, Catpil/Kampus) dan pendaftaran (`pendaftar_status`, Kesra) — WAJIB selalu dibuka di "— Pilih —". Jangan pernah pakai nilai tersimpan sebagai default (`old('status', $decision['status'])`), walau label form sudah "Ubah Keputusan". Alasannya: admin bisa cuma membuka halaman lalu menekan simpan, dan keputusan lama terkirim ulang sebagai keputusan baru — menimpa `diputuskan_at` dan `diputuskan_oleh` tanpa ada keputusan yang sebenarnya diambil. Nilai lama cukup ditampilkan read-only di kotak "Keputusan saat ini" / badge status. `old()` tetap dipakai supaya pilihan tidak hilang saat validasi gagal. Berbeda dengan form pendaftaran beasiswa mahasiswa, yang memang memakai nilai tersimpan sebagai default.

## Antrean Kesra punya view sendiri, terpisah dari daftar profil
Catpil dan Campus berbagi `index.blade.php` (kolom dari peta `$stageColumns`); Kesra punya `kesra.blade.php` sendiri karena sumber datanya baris `pendaftar` — kolom, filter, dan aksi berbeda bentuk. Kesra tidak dipaginasi, konsisten dengan dua halaman lain. Label statusnya selalu lewat `Applicant::STATUS_LABELS`/`statusLabel()`/`statusBadge()`, dan kolom Kampus lewat `prodi.fakultas.kampus.nama_kampus` (bukan `->nama`). Opsi "Semua Status" bernilai `Applicant::FILTER_ALL`, bukan string kosong. Header halaman ini memuat SATU tombol: **"Unduh Excel"** (`route($routePrefix.'.export', request()->only('filter'))`, guard `hasMenuAccess($routePrefix.'.export')`) — pola sama dengan Catpil/Kampus; unduhan berisi status yang sedang dibuka (default antrean `verifikasi`). Tombol "Disetujui" (`fa-check-double`) tetap TIDAK ada — pintu ke arsip lewat dropdown sidebar Kesra (menu "Keputusan"); `KesraDisetujuiTest` mengunci `assertDontSee('fa-check-double')` pada `admin.kesra.index`.

## Arsip "Disetujui" adalah view ketiga, bukan filter keenam di antrean
`kesra-disetujui.blade.php` menampilkan `pendaftaran('diterima')` saja (halaman `admin.kesra.disetujui`), bukan `kesra.blade.php` dengan filter status yang diubah — antrean putusan harus tetap default-nya yang menunggu. Kolomnya menampilkan `diputuskan_at` + `diputuskanOleh->username` (BUKAN `decidedByName()`: helper itu membaca atribut `name` yang tidak ada di `users`, jadi selalu null) dan tiap baris membawa form Hapus DELETE dengan `.btn-delete`. Jangan menambahkan filter status atau pagination ke halaman ini. Header halaman ini sengaja TANPA tombol apa pun (permintaan pengguna): "Unduh Excel" ada di halaman antrean Kesra, dan tombol "Antrean Putusan" juga SUDAH DIHAPUS — navigasi cukup lewat breadcrumb dan dropdown sidebar; tes `VerifikasiExportTest` mengunci `assertDontSee('Unduh Excel')` dan `KesraDisetujuiTest` mengunci `assertDontSee('Antrean Putusan')` pada halaman ini.

## Form keputusan Kesra di lihat.blade: label + bintang, tanpa Catatan
Di `admin/verifikasi/lihat.blade.php` cabang `$stage === 'kesra'`, heading "Keputusan Kesra"/"Ubah Keputusan" adalah `<label for="pendaftaran_status" ...>` (kelas styling lama dipertahankan + `d-block`) dengan `<span class="text-danger">*</span>`, dan select-nya diberi `id="pendaftaran_status"`. Teks labelnya harus dipertahankan: tes `VerifikasiUiTest` mengunci `Keputusan Kesra`/`Ubah Keputusan`. Input `pendaftaran_catatan` (dulu berlabel "Alasan"/"Catatan") SUDAH DIHAPUS total dari alur Kesra -- jangan ditambahkan kembali; `VerifikasiUiTest` mengunci `name="pendaftaran_catatan"` TIDAK ada.

## View status verifikasi: rekap read-only, tanpa Aksi, dropdown lokasi dinamis
Halaman `status.blade.php` (menu "Status Verifikasi", route `admin.kesra.status`) menampilkan rekap status profil (kolom No/Nama/NIM/Kampus/Fakultas/Jurusan + tiga badge verifikasi) untuk kesra, super_admin, Catpil, dan Kampus -- TANPA kolom aksi ("Putuskan" sudah dihapus, `$bisaAksi` tidak lagi dipakai). Form keputusan Kesra (`lihat.blade.php`) kini tanpa input `pendaftaran_catatan` sama sekali (istilah "Alasan"/"Catatan" sudah tidak dipakai di alur admin). Kartu kesra berjudul "Keputusan Kesra" (bagian dalam "Detail Beasiswa" menampilkan data beasiswa), H1 halaman "Detail Beasiswa", memuat select "Keputusan Kesra".

## View status verifikasi: breadcrumb, kolom Jurusan, filter bertingkat server-side
status.blade.php: breadcrumb hanya Dasbor > Status Verifikasi (tanpa link admin.kesra.index yang 403 untuk Catpil/Kampus); kolom "Program Studi" ditampilkan dengan judul "Jurusan" (sumbernya Prodi); filter status pakai `verif_catpil`/`verif_kampus`, filter lokasi `kampus_id`/`fakultas_id`/`jurusan_id` dengan select fakultas/jurusan TIDAK disabled ("-- Semua ... --") dan opsinya DINAMIS (Fakultas hanya milik kampus terpilih, Jurusan hanya milik fakultas terpilih) dari `VerifikasiController::status()`; nilai yang melanggar hirarki di-null-kan. Dua grup filter dipisah spasi saja, TANPA garis horizontal (border-top). Alert "hanya memverifikasi profil yang seluruh tahap sebelumnya sudah disetujui" DIHAPUS dari index.blade.php (keras berlaku, jadi tidak perlu alert).

## Status page is a read-only rekap; dynamic location cascade, no divider
status.blade.php has NO action column: columns are No, Nama, NIM, Kampus, Fakultas, Jurusan + three verif badges (Catpil/Kampus/Kesra). All four roles (kesra, super_admin, catpil, kampus) open it read-only; nothing is decided there. Filters are two groups separated by spacing ONLY -- NO border-top/horizontal line. Status filters stay `verif_catpil`/`verif_kampus`. Location selects (kampus_id/fakultas_id/jurusan_id) are never `disabled` and their options are DYNAMIC (cascade): Fakultas lists only fakultas of the selected kampus, Jurusan lists only prodi of the selected fakultas (or of the selected kampus while fakultas is empty). VerifikasiController::status() still nulls a sub-value that contradicts a selected parent (soft coherence), but a single-level pick without its parent stays valid. "Jurusan" = Prodi (no jurusan table).

### Kolom Kesra dibaca dari `pendaftar`, bukan `verif_kesra`
Di `status.blade.php` kolom **Verifikasi Kesra** memakai `$user->kesraDecision()` (turunan baris `pendaftar.status`: ada `diterima` => Disetujui, selain itu `ditolak` => Ditolak, sisanya Menunggu), BUKAN `$profile->verifStageDecision('kesra')`. `verif_kesra` ditulis `setuju` untuk semua keputusan Kesra, jadi membacanya akan menampilkan pendaftaran DITOLAK sebagai "Disetujui". `VerifikasiController::status()` ikut eager-load `applicants` (satu query, tanpa N+1). Pemetaan label/warna ada di `UserProfile::decisionForStatus()` (dipakai `verifStageDecision()` juga). Kolom Catpil/Kampus tetap dari `verifStageDecision()`.

## Kesra card header "Keputusan Kesra", section "Detail Beasiswa", scholarship rows
In admin/verifikasi/lihat.blade.php the page H1 stays "Detail Beasiswa" and the `$stage === 'kesra'` card HEADER now reads "Keputusan Kesra"; the inner grid heading reads "Detail Beasiswa" and its rows show BEASISWA data (`$detailBeasiswa`: Kampus, Kuota, IPK Minimal, Semester Minimal, Tingkat Gelar, Status Beasiswa, Tanggal Mulai, Tanggal Selesai) — NOT applicant/registrant data, which already lives in the left `partials.profil-detail` column. The card also holds the `Keputusan Kesra` select form. The `pendaftaran_catatan` textarea/field is GONE from the Kesra decision flow: KeputusanPendaftaranRequest has no catatan/`required_if` rule and KeputusanPendaftaranController::update() writes `catatan => null`. Do not re-add a Catatan input or label there; VerifikasiUiTest asserts `name="pendaftaran_catatan"` is ABSENT and KesraDisetujuiTest/BeasiswaPendaftaranTest assert a fresh decision leaves `pendaftar.catatan` null. (The student page user/beasiswa/lihat still shows the "Alasan" copy with a fallback.)
